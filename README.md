# Радио КП — Прямой эфир (0.7.7)

Минималистичный Android-плеер для прослушивания эфира Радио КП без вывода и декодирования видеодорожки.

## Источники

1. **VK Видео** — основной источник. Приложение открывает `https://vkvideo.ru/@radiokp/lives`, обнаруживает HLS URL в ответе `video.getVideoDiscover`, передаёт ссылку в Media3 и уничтожает WebView после нахождения потока.
2. **RuTube** — резервный источник. Приложение открывает официальный канал `https://rutube.ru/u/radiokp/`, отслеживает запросы `api/play/options`, извлекает HLS только когда ответ помечен `is_live=true`. Архивные записи не должны приниматься за живой эфир. Для этого используется неофициальная, наблюдаемая структура API; RuTube может её изменить.
3. **Радио КП** — последний резерв. Используются опубликованные на официальном сайте московские MP3-потоки 32 / 64 / 128 кбит/с: `kpradio32.streamr.ru`, `kpradio64.streamr.ru`, `kpradio128.streamr.ru`. Официальная страница: https://radiokp.ru/about. Эти ссылки могут перенаправлять на `kpradio.hostingradio.ru:8000`.

## Качество аудио

- VK и RuTube настраиваются **раздельно**. Ограничение задаётся через Media3 для аудиодорожек HLS. Оно работает, если платформа публикует несколько аудиодорожек/вариантов. Приложение не может перекодировать исходный поток на телефоне.
- Радио КП: выбор переключает реальные московские адреса 32 / 64 / 128 кбит/с. По умолчанию 64 кбит/с.
- Для VK/RuTube при единственном варианте потока настройка может не уменьшить фактический трафик; если в HLS звук и видео объединены в одних сегментах, отключение декодирования видео само по себе не гарантирует, что видеоданные не скачиваются.
- Для видеоисточников по умолчанию установлен предел 64 кбит/с. Это ограничение выбора доступной аудиодорожки, а не перекодирование потока на телефоне.

## Возможности

- Автозапуск основного источника VK при открытии приложения (включён по умолчанию).
- Раздельные настройки максимального аудиобитрейта для VK и RuTube, отдельный выбор реального радио-потока 32/64/128 кбит/с.
- Автоматический переход VK → RuTube → Радио КП при ошибке воспроизведения или таймауте обнаружения трансляции.
- Ручной выбор / переключение источников предыдущий/следующий. Во время поиска страница платформы скрыта; при необходимости её можно временно открыть кнопкой «Показать страницу VK/RuTube».
- Старт, пауза, продолжение и стоп.
- Отображение продолжительности прямого эфира от временной метки в метаданных VK/RuTube; время не начинается заново при переключении источника или переподключении. Если надёжная временная метка не найдена (например, у радиопотока), отображается просто `LIVE`.
- Раздельные настройки качества VK и RuTube; отдельный выбор реального битрейта третьего источника Радио КП; автозапуск и авто-переключение.
- Фоновое воспроизведение нативным Media3 в foreground service и управление из уведомления.
- Видеодорожка отключена через Media3 TrackSelector. Временный WebView используется только на этапе обнаружения трансляции, по умолчанию он скрыт и не занимает место на экране; кнопку «Показать страницу» можно нажать для ручного выбора LIVE. Изображения не загружаются, найденный поток передаётся нативному плееру, после чего WebView полностью уничтожается.
- Для радио разрешён cleartext только на четырёх доменах, необходимых для официальных потоков и редиректа; остальной cleartext заблокирован.

## Ограничения и статус проверки

Это экспериментальная интеграция с платформенными видеосервисами. Внутренние механизмы VK и RuTube не являются стабильными публичными API и могут меняться. Поток VK уже был воспроизведён пользователем в предыдущей версии. Интеграция RuTube и автоматическое переключение источников ещё не проверялись на действующей трансляции. Вне эфира приложение закономерно не сможет проверить эти два видеоканала.

В режиме радио возможен известный обрыв примерно через 40 минут, о котором сообщил пользователь. Плеер делает до двух повторных подключений к выбранному потоку с короткой задержкой. Поэтому радио оставлено третьим резервом, а не основным источником.

Прогресс в интерфейсе показывает состояние соединения/live и время прослушивания, а не позицию перемотки: прямой эфир не имеет надёжной фиксированной длительности или доступной перемотки в нативном аудиопотоке.

## Сборка через GitHub Actions (без Android Studio на ПК)

1. Загрузите содержимое проекта в корень существующего GitHub-репозитория, сохранив пути файлов и папку `.github`.
2. Commit changes запускает workflow автоматически. Вкладка **Actions** показывает статус.
3. При успешном запуске скачайте артефакт `radio-kp-live-apk` и извлеките `app-debug.apk`.

Workflow скачивает Gradle напрямую и не использует `gradlew`, поскольку в zip не вкладывается бинарный Gradle Wrapper JAR.

## Установка обновления

Application ID остаётся `ru.radiokp.voennoerevue`, versionCode увеличен до 4. Если Android не разрешит установить поверх предыдущей debug-сборки из-за отличающейся подписи, потребуется удалить старое приложение и установить новый APK. При удалении локальные настройки будут сброшены.

## Диагностика аудиопотока (0.7.1)

Во время воспроизведения VK и RuTube статус в карточке подключения сохраняет результат анализа HLS:
- **Отдельная аудиодорожка HLS** — платформа опубликовала отдельный audio rendition, плеер использует его плейлист.
- **Аудио-only вариант HLS** — в мастер-манифесте найден вариант с аудиокодеком без видеокодека.
- **Отдельная аудиодорожка или аудио-only вариант не объявлены** — плеер использует исходный HLS; отключение видеодекодирования не гарантирует отсутствия загрузки видеоданных.
- **Не удалось проверить HLS-манифест** — отображается HTTP-код или класс сетевой/парсинговой ошибки. В этом случае нельзя делать вывод, что отдельной аудиодорожки у платформы нет.

Если отдельная аудиодорожка не воспроизводится, плеер возвращается к исходному HLS и сохраняет это в статусе.

Диагностика показывает структуру плейлиста и выбранный плеером режим; она не измеряет расход трафика сама по себе. После установки нужно сравнить скорость передачи данных в одинаковых условиях.

## Перебор вариантов HLS (0.7.2)

- Из ответа VK извлекаются все допустимые HLS URL, с приоритетом `hls_live` и `hls_live_playback`.
- Из ответа RuTube извлекаются все HLS URL внутри `live_streams.hls`; при явной live-метке допускаются и другие HLS URL того же ответа.
- За один запуск проверяется до 8 адресов. Для каждого проверяется наличие отдельной HLS audio rendition или audio-only variant.
- Если отдельный аудиоплейлист найден в одном из вариантов, запускается он; при ошибке воспроизведения fallback идёт на соответствующий мастер-плейлист.
- Если ни один вариант не содержит отдельного аудиоплейлиста, запускается основной HLS URL и в статусе отображается количество проверенных вариантов.

Версия 0.7.3 добавляет поиск DASH/MPD в live-метаданных RuTube и проверку отдельного аудиопредставления в AdaptationSet. Если отдельное аудиопредставление найдено, оно запускается через Media3 DASH с отключённой видеодорожкой. При ошибке воспроизведения приложение возвращается к HLS. Если API не отдаёт MPD или в нём нет отдельного аудио, сохраняется прежнее поведение HLS.

## Изменения версии 0.7.4 — диагностика RuTube HLS/HDS

- Из live_streams извлекаются до четырёх HDS/F4M URL, отдельно от HLS и DASH.
- F4M-манифесты читаются только для диагностики: считаются media-варианты и проверяются явные audio-only метаданные.
- HDS/F4M не передаётся в Media3, поскольку штатного модуля воспроизведения HDS нет.
- Для HLS без отдельного аудио отображается тип манифеста: master или media playlist; число вариантов, AUDIO rendition, URI и связанные группы; если доступны — диапазон BANDWIDTH.
- VK HLS-путь и найденная оптимизация 0.7.x не изменяются.
- `versionCode=11`, `versionName=0.7.4`.

Сборка собирает дополнительную диагностику для следующего теста LIVE RuTube; снижение трафика не обещается, пока не найден воспроизводимый отдельный аудиопоток.

## Изменения версии 0.7.6 — снижение трафика RuTube

- Если RuTube не публикует отдельную HLS-аудиодорожку или audio-only вариант, приложение выбирает дочерний HLS-вариант с наименьшим заявленным AVERAGE-BANDWIDTH/BANDWIDTH.
- Оптимизация применяется только к RuTube. VK продолжает использовать прежний поиск отдельной аудиодорожки.
- Если выбранный низкобитрейтный плейлист не запускается, приложение возвращается к исходному master HLS.
- Это по-прежнему комбинированный аудио+видео сегментный поток, а не гарантированный audio-only режим; реальную экономию нужно измерить на LIVE.
- `versionCode=13`, `versionName=0.7.6`.


## Изменения версии 0.7.7 — реальное время начала LIVE

- В метаданных VK/RuTube ищутся только явные поля фактического старта LIVE: `live_started_at`, `live_started_ts`, `stream_started_at`, `broadcast_started_at`, `actual_start_time` и `started_at` внутри объекта с признаком текущего LIVE.
- Поле VK `live_start_time` исключено: оно обозначает запланированное время начала, а не фактический старт. Поля RuTube `created_ts` / `publication_ts` также исключены: это время создания/публикации карточки, а не подтверждённое начало эфира.
- Неоднозначные даты без часового пояса не используются, чтобы не получить неверное время из-за локальной зоны устройства.
- Таймер рассчитывается по абсолютной метке времени эфира, а не по моменту подключения плеера. Переключение источника, буферизация и повторное подключение его не обнуляют в рамках текущей сессии приложения.
- Для потока без достоверной временной метки (включая радиопоток) отображается просто `LIVE`.
- `versionCode=14`, `versionName=0.7.7`.
